# Saved views

A **view** is a saved way of looking at issues: a query, a layout and how the result is shown. Open **Filters > Views**
(`/views`). The feature can be switched off under Administration > Features and modules (id `views`); the API then
answers 404 and the menu entry disappears. Stored views are kept.

## What a view contains

| Part | Values |
|---|---|
| Query | JQL, and/or simple filters (projects, statuses, types, priorities, labels, assignee, reporter, text, open/resolved). Both are combined with AND. |
| Layout | list, table (sortable column headers), board, calendar (due date, start date, created or updated), timeline (start date to due date) |
| Display properties | which columns, and their order (key, summary, type, status, priority, assignee, reporter, project, labels, components, fix versions, sprint, story points, created, updated, resolved, resolution, due date, start date) |
| Sort | up to three terms; when empty the JQL `ORDER BY` applies, else newest first |
| Group by / sub-group by | status, assignee, priority, type, label, sprint, none. On the board, groups are columns and sub-groups are swimlanes. |
| Show empty groups | adds buckets with no issues for status, priority and type |

## Sharing and permissions

Views use the same sharing model as saved filters: private (default), everybody who can sign in, specific users,
groups (you must be a member), or projects (members who can browse the project). Only the owner or an administrator
changes or deletes a view. A view you cannot see answers 404.

A view only stores the query. It is **always executed as the person looking at it**, restricted to the projects that
person can browse, so sharing a view never reveals an issue. Exports follow the same rule.

## Built-in views

*All work*, *Assigned to me*, *Created by me* and *Recently updated* exist for everybody. They are generated by the
server, cannot be edited or deleted, but can be favourited and duplicated (the copy is yours).

## The view page

`/views/<id>` shows the chosen layout with controls for layout, group by, sub-group by, show empty groups, display
properties and the query. Changes are applied immediately but not saved: a bar offers **Save changes** (owner),
**Save as new view** and **Reset**. The settings you used last are remembered per browser and per view
(local storage) until you save or reset.

Notes: grouping covers the issues of the loaded page (100 for list and table, 500 for board, calendar and
timeline). The page shows a note when there are more pages.

## Export

From the view page, **Export** downloads CSV, Excel (XLSX) or JSON of the current configuration, including unsaved
changes. At most **10,000 rows** are exported (`X-Export-Truncated: true` and a notice in the UI when cut off);
`VIEWS_EXPORT_MAX_ROWS` can lower the cap. CSV and JSON are streamed in chunks of 500 issues; the XLSX is built in
memory (zero-dependency writer, one sheet, bold frozen header row).

Text cells that start with `=`, `+`, `-` or `@` (or a tab / carriage return) are prefixed with an apostrophe in
CSV and XLSX so spreadsheet programs do not evaluate them. JSON keeps the raw text. CSV has a UTF-8 byte order mark so
Excel reads accents correctly. Each export is written to the audit log (`VIEW_EXPORTED`: who, format, row count,
query summary, never the issue content).

## API

All routes need a session. `:id` is numeric; built-ins use `builtin/:key`
(`all-work`, `assigned-to-me`, `created-by-me`, `recently-updated`).

| Route | Purpose |
|---|---|
| `GET /rest/api/2/views?scope=all\|mine\|shared\|favourites&search=` | List (built-ins in `builtin`, stored views in `values`) |
| `POST /rest/api/2/views` | Create `{name, description?, config, shares?, favourite?}` |
| `GET/PUT/DELETE /rest/api/2/views/:id` | Read, update (config is replaced as a whole), delete |
| `POST /rest/api/2/views/:id/duplicate`, `PUT .../favourite` | Duplicate, favourite `{favourite}` |
| `GET /rest/api/2/views/:id/issues?startAt&maxResults` | Execute as the caller: `issues`, `total` and `groups` (ids per group and sub-group) |
| `GET /rest/api/2/views/:id/export?format=csv\|xlsx\|json` | Export |
| `POST /rest/api/2/views/execute`, `POST /rest/api/2/views/export` | Same for an unsaved configuration `{config, format}` (for example a search result) |
| `GET /rest/api/2/views/builtin/:key[/issues\|/export\|/duplicate\|/favourite]` | Built-in views |

Bodies are validated strictly (unknown keys are rejected); JQL goes through the same validator as saved filters.
Personal access tokens with limited scopes cannot reach these routes (scope family "other").

## Limits

No inline editing in the table, no drag and drop on the board layout, no timeline dependencies, no publishing a view to
people without an account. Not verified in a real browser (type check, build, unit and integration tests only).
